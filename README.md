# PRAS - 탐라는 전기예보제

제주지역 주택용 TOU 및 전기차 자가소비용 고객을 대상으로, 태양광 발전량이 많은 시간대의 요금 할인과 부하이전이 고객·한전·계통에 미치는 영향을 분석하기 위한 웹 시뮬레이터입니다.

업로드된 엑셀의 원자료와 수식을 항목별로 점검한 시간대별 계산엔진이 연결되어 있으며, 입력조건과 부하이전 시나리오를 변경하면 고객·한전·계통 결과가 즉시 재계산됩니다.

## 현재 구현 범위

- 분석연도, 고객유형, 고객 수, 참여율, 할인율 입력
- 계절 3개와 주중·주말 부하곡선 선택 및 연도 전체 분석 지원
- 주말할인 중복 적용 우선순위 설정
- 주택용 전체부하 균등이전과 13개 주요 가전 선택이전 분리
- 선택 발령조건에 따른 가전별 최대 이전비중 자동 산정 및 0~최대 개별 조절
- 전기차 전체·완속·급속 고객유형과 EV 시나리오 1·2-1·2-2
- 주택용 이전 가능 주요 가전 13종 개별 선택
- 시간대별 부하곡선 및 월별 발령현황 표시
- 커서·키보드로 시간별 수치를 확인할 수 있는 24시간 꺾은선 부하곡선
- 고객·한전·계통 관점의 결과 화면 구분
- 2024·2025·2026 YTD 발령실적과 월별 현황
- 시간대별 부하·요금·SMP 재계산 엔진 및 자동 회귀검사
- PC·모바일 반응형 화면
- GitHub Pages 자동 배포

## 저장소 구조

```text
app/                         화면과 스타일
lib/simulator/               시간대별 계산엔진·기준자료·타입·기본값
data/                        입력자료 형식 및 CSV 템플릿
docs/CALCULATION_ENGINE.md   계산방법·기준점·가정
docs/LOGIC_AUDIT.md          원자료 오류와 수정조치
.github/workflows/           GitHub Pages 자동 배포
next.config.ts               GitHub Pages 정적 배포 설정
```

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm ci
npm run dev
```

계산 로직, 코드 형식과 타입을 확인할 때는 다음 명령을 사용합니다.

```bash
npm run lint
npm run typecheck
npm run test:engine
```

GitHub Pages용 정적 파일을 로컬에서 만들 때는 다음 명령을 사용합니다.

```bash
GITHUB_PAGES=true npm run build:github-pages
```

생성된 정적 파일은 `out/` 폴더에 저장됩니다.

## GitHub 저장소 및 Pages 설정

1. GitHub에서 `pras-tamra-forecast` 저장소를 생성합니다.
2. 이 프로젝트의 전체 파일을 저장소 `main` 브랜치에 올립니다.
3. 저장소의 `Settings > Pages`에서 배포 소스를 `GitHub Actions`로 선택합니다.
4. `main` 브랜치에 변경사항이 올라오면 배포 작업이 자동 실행됩니다.
5. 일반 프로젝트 저장소의 주소는 `https://<계정명>.github.io/pras-tamra-forecast/` 형식입니다.

저장소 이름이 달라져도 배포 작업이 해당 이름을 자동으로 경로에 반영합니다.

> 중요: `Deploy from a branch`를 선택하면 시뮬레이터가 아니라 이 README 문서가 웹페이지로 표시될 수 있습니다. 반드시 `GitHub Actions`를 선택합니다.

## 계산엔진 처리 순서

1. 실적 발령구간 또는 시간별 SMP 조건으로 이벤트 마스크 생성
2. 고객유형·시나리오별 시간대 부하이전 및 에너지 보존
3. 기본요금과 현행·할인 시간별 단가로 고객요금 재계산
4. 시간별 부하차와 SMP로 한전 구입비 변화 산정
5. 고객·한전·계통 결과를 동일 기준으로 집계

세부 산식은 [계산엔진 문서](docs/CALCULATION_ENGINE.md), 발견한 오류와 수정조치는 [로직 점검 보고서](docs/LOGIC_AUDIT.md)를 참고합니다.

## 자료 관리 원칙

- 원본자료는 변경하지 않고 별도 보관합니다.
- 시뮬레이터 입력자료는 `data/`의 표준 열 이름으로 변환합니다.
- 원 단위, kWh 단위, 시간대 기준과 부가세·기금 포함 여부를 명시합니다.
- 계산 결과에는 적용한 데이터 기준연도와 엔진 버전을 함께 기록합니다.
